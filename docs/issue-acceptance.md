# Predecessor issue acceptance

Audited 2026-08-21 from the complete GitHub issue lists for the three predecessor extensions. Pull
requests are not counted as issues. This ledger covers all 36 issues: 12 from
`hangxingliu/vscode-systemd`, 10 from `dviererbe/vscode-systemd`, and 14 from
`bearmini/vscode-systemd-unit-file`. The upstream section additionally tracks the 19 systemd,
Podman, and mkosi issues that directly constrain the extension's parser, validator, and static
configuration behavior.

`Implemented` means the behavior exists in this repository and has a named automated check.
`Release control` means the implementation and verification are complete, but publishing remains
intentionally unexecuted until the maintainer approves a release. `Excluded` is reserved for live
service-manager behavior outside this authoring extension's product boundary. `Upstream-dependent`
means an upstream defect or missing interface remains open, while this extension has an explicit
local guardrail and does not depend on that issue being resolved.

## Product boundary

This is an authoring, static-analysis, and validation extension—not a service-manager UI. The five
excluded dviererbe issues all require reading or mutating live runtime state. Adding them would
require `systemctl` or D-Bus access, introduce platform and privilege coupling, make the Explorer
poll host state, and conflict with browser, virtual-workspace, and Restricted Mode support.

The boundary does not reduce authoring intelligence: unit/resource references, effective
configuration, template resolution, source precedence, masks, dependency graphs, and safe
workspace-owned edits remain in scope and are tested independently of a running Linux host.
